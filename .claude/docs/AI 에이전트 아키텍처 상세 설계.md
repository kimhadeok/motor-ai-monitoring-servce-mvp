아키텍처 핵심 흐름 : "이벤트 수신 ➔ 알림 + 컨텍스트 및 RAG 결합 ➔ LLM 추론 및 툴 실행 ➔ 리포트 생성"

[ 1. 이벤트 수신 및 트리거 계층 ]
  └─ 메시지 큐 (RabbitMQ / Redis Pub/Sub) ──> 이벤트 수신 (DANGER 진입 등)
        └─ 에이전트 라우터 ──> 불필요한 중복 호출 차단 후 에이전트 코어 구동

[ 2. 컨텍스트 및 메모리 결합 계층 ]
  └─ 컨텍스트 매니저 ──> 진단 대상 모터 정보 집약
        ├─ [단기 버퍼] ────> 직전 1시간 윈도우 데이터 (온도, 진동, 속도, 소리 변화 양상)
        ├─ [장기 트렌드] ──> 최근 6시간 거시적 데이터 (돌발 vs 점진적 악화 판정)
        └─ [RAG 지식베이스] ─> Vector DB에서 제조사 매뉴얼 및 과거 유사 장애 이력 검색

[ 3. 추론 및 도구(Tool) 실행 계층 ]
  └─ LLM 코어 엔진 ──> 실시간 수치 + 맥락 + RAG 매뉴얼 종합 분석
        ├─ [시계열 패턴 분석 툴] ──> 특정 주파수 및 진동 급증 등 이상 패턴 수치 검증
        ├─ [장애 원인 추론 툴] ──────> 현상별 고장 원인 역추적
        └─ [대응 매뉴얼 조회 툴] ───> 정비 가이드 및 표준 조치 사항 매칭

[ 4. 진단 결과 합성 및 출력 계층 ]
  └─ 진단 결과 합성기 (Synthesizer) ──> 구체적인 원인 분석 및 대응 조치 리포트 생성
        └─ 대시보드 UI / 관리자 알림 ──> 컬러 코딩 변경 및 긴급 정비 가이드 최종 표출
