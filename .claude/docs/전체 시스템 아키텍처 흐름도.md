[ 1. 현장 및 데이터 수집 계층 ]
└─ 기계 모터 ──> (온도, 진동, 속도, 소리 / 10초·20초·30초 주기) ──> Edge / 센서 데이터
└─ [분기 1] 센서 데이터 API 연결 ───────> 48시간 DB 저장
└─ [분기 2] 센서 데이터 API 연결 ───────> 48시간 DB 저장
├─ [분기 2] 프론트엔드 실시간 대시보드 ──> 그래프 실시간 렌더링
└─ [분기 3] 백그라운드 프로세스 ───────> DB에 저장된 데이터 체크 (값이 등록되고 있는지 확인. 진행이 중간된 프로세스 진행 (예 : pdf 생성 중 멈춤 것 등))

[ 2. 상태 분석 및 필터링 계층 ]
└─ 데이터 분석 ──> 상태 분류 (NORMAL / WARNING / DANGER / FAULT) 및 DB 적재
├─ NORMAL / WARNING ──> 로그 적재 & 맥락 유지 (알람 핑퐁 방지)
├─ DANGER 진입 ────────> 쿨다운 타임 체크 (중복 개입 방지)
└─ FAULT ──────────────> 사후 분석용 리포트 대기 모드

[ 3. AI 에이전트 가동 및 이벤트 중계 계층 ]
└─ 쿨다운 타임 통과 시 ──> AI 에이전트 가동 (1시간 데이터 + 상태값 + RAG 매뉴얼 결합 진단)
├─ 상태 전이 발생 (예: WARNING ➔ DANGER)
└─ 메시지 큐 발행 (메시지 중계 시스템: RabbitMQ / Redis Pub/Sub)

[ 4. 최종 사용자 알림 및 UI 피드백 계층 ]
└─ 메시지 큐 수신 ──> 관리자 알림 발송 & 대시보드 상태 색상(컬러 코딩) UI 업데이트


2. 단계별 상세 프로세스 흐름
[ 1단계: 실시간 데이터 수집 및 엣지 처리 ]
  └─ 모터 센서 (온도, 진동, 속도, 소리) ──> (10초/20초/30초 주기) ──> 시스템 인입
        ├─ [프론트엔드] ──> 실시간 멀티 시계열 그래프 즉시 렌더링
        └─ [AI 에이전트] ──> 1시간(실시간 진단) 및 6시간(트렌드) 윈도우 버퍼/캐시 관리 or DB 저장

[ 2단계: 4단계 상태(State) 분류 및 필터링 ]
  └─ 수집된 데이터 분석 ──> 상태 판정
        ├─ NORMAL  ────────> 정상 운전 (실시간 모니터링 유지)
        ├─ WARNING ────────> 주의 (이벤트 로그 누적, 전조 증상 맥락 활용)
        ├─ DANGER  ────────> 위험 (AI 에이전트 즉시 출동 대상)
        └─ FAULT   ────────> 고장/정지 (사후 분석용 리포트 대기)

[ 3단계: 상태 전이(State Transition) 및 이벤트 제어 ]
  └─ 상태 값 변경 감지 (NORMAL ➔ WARNING)
        ├─ 쿨다운 타임(2시간) 확인 (설정 시간 내 중복 개입 차단으로 알람 폭탄 방지)
        └─ 조건 충족 시 ──> 내부 메시지 큐(RabbitMQ / Redis Pub/Sub)에 이벤트 '딱 1개' 발행
  └─ 상태 값 변경 감지 (WARNING ➔ DANGER)
        ├─ 쿨다운 타임(1시간) 확인 (설정 시간 내 중복 개입 차단으로 알람 폭탄 방지)
        └─ 조건 충족 시 ──> 내부 메시지 큐(RabbitMQ / Redis Pub/Sub)에 이벤트 '딱 1개' 발행

[ 4단계: AI 진단 및 UI 피드백 ]
  └─ 메시지 큐 이벤트 수신
        ├─ [AI 에이전트] ──> 1시간 데이터 + 상태값 + RAG 매뉴얼 결합 진단
        └─ [대시보드 UI] ──> 모터별 상태 색상 변경(컬러 코딩) 및 알림 표출
