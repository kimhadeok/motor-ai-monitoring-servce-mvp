## 2. 예열이 무효가 되는 조건 — **이것이 핵심이다**

**너무 일찍 예열하면 소용이 없다.** 부팅 시 최신 텔레메트리가 `DEMO_DATA_MAX_AGE_HOURS`(2시간)보다 오래되면 `bootstrap`이 **DB 파일을 통째로 지우고** 다시 만든다(`02 §6.1`, `05 §6.2`). 리포트 캐시는 `motor_status_logs.report_html`에 들어 있으므로 **DB와 함께 사라진다.** 즉 예열해 둔 리포트가 전부 날아가고, 시연에서 다시 5~9초를 기다린다.

- 앱이 계속 떠 있으면 런타임 틱이 텔레메트리를 이어 붙여 신선도가 유지된다 → 재시드 조건에 걸리지 않는다.
- 따라서 **예열 후 시연까지 탭을 닫지 말고 열어 둔다.**
- **미확인**: Streamlit Community Cloud가 유휴 앱을 재우는지, 재운다면 깨어날 때 프로세스가 새로 뜨는지는 확인하지 않았다. 새로 뜬다면 위 재시드가 그대로 발생한다. **안전한 가정은 "재워질 수 있다"이고, 대응은 시연 직전 예열 + 탭 유지다.**

## 3. 절차

### 시연 30분 전
1. 배포본 URL을 연다. **부팅 7초를 여기서 소진한다** (시드 축소 전에는 23초였다).
2. `demo1@hankuk-motors.co.kr` / `demo1234!` 로그인 → 대시보드 타일 4칸이 채워지는지 확인.
3. **이 탭을 닫지 않는다.** 시연까지 그대로 둔다.

### 시연 10분 전 — 리포트 예열
이벤트 목록에서 아래를 **각각 한 번씩 열었다 닫는다.** 첫 건만 5~9초, 이후는 4초대이고, 시연에서 다시 열면 0.03초다.

| 우선순위 | 모터 | 왜 이걸 여는가 |
|---|---|---|
| 1 | **MTR-001 · 2호기 메인 송풍기** (DANGER) | 시나리오가 **베어링 윤활 부족**이다 — 온도·진동이 함께 오르는 유일한 케이스라 AI 진단의 "연쇄 영향"이 가장 설득력 있게 나온다 (`seeding.py _SCENARIOS`) |
| 2 | FAULT 4대 중 1대 (137·143·157·167호기) | 정비 완료 확인 흐름과 이어 붙일 리포트 |

### 무대 동선 — 관리자는 곧바로 [지표 임계값] 탭으로

`관리자`를 누르면 **조회 전용인 고객 회사 탭이 먼저 열린다**(`admin.py`의 탭 순서: 고객 회사 → 담당자 → 모터 → 지표 임계값). 시연에서 관리자로 가는 이유는 임계값 데모 하나이므로, 화면이 뜨자마자 **네 번째 탭을 바로 누른다.**

> 탭 순서를 코드로 바꾸지 않는 이유: 실제 제품의 정보 순서는 회사 → 담당자 → 모터 → 임계값이 맞다. 무대에서 탭을 더듬는 3초는 동선을 정해 두면 없어진다(고객 의견 2차 3-(4)).

## 4. 왜 코드로 안 푸는가

"부팅 때 리포트를 미리 생성"은 **2026-08-07에 일부러 걷어낸 설계**다. 전건 생성이 콜드 스타트를 지배해 온디맨드로 옮겼고 **8.80초를 줄였다**(`remaining_work` #9, #1의 (B)). 되돌리면 이미 23초인 배포 부팅이 더 길어져 문제를 키운다. 예열은 사람이 클릭 몇 번으로 끝내는 편이 싸다.

## 5. 시연 중 나올 질문에 대한 답 (고객 의견 3-(4))

화면이 10초마다 움직이는 것을 보여주면 **"지금 새 이상이 생기면 어떻게 됩니까"** 가 반드시 나온다. 개발팀과 답이 엇갈리면 신뢰가 한 번에 깎이므로 문장을 맞춰 둔다.

> "오늘 보시는 것은 **감지된 이상을 다루는 부분**입니다. 감지 자체 — 실시간 전이 판정과 통신 두절 감지 — 는 상시 실행 경로가 필요해서 **실증(PoC) 단계에서 실센서와 함께 붙입니다.**"

사실관계(이 문장이 과장이 아닌 근거):
- 런타임 틱은 텔레메트리만 이어 붙이고 `motor_status_logs`에 쓰지 않는다 (`services/runtime_tick.py run_tick()`). 그래서 앱을 켜 둔 동안 **새 이벤트는 생기지 않는다.**
- 값은 자기가 속한 상태 구간 안에서만 흔들려 **카드 색도 바뀌지 않는다** (실측: 틱 3회 후 상태 변경 0대).
- 화면의 FAULT 4대·DANGER 13대는 부팅 시 시드가 만든 전이 80건이 전부다.
- 이 범위는 문서에 명시된 확정 사항이다 — `remaining_work` #2-1·#2-3, README "MVP 범위 밖".

**하지 말아야 할 답**: "실시간으로 감지합니다." 관리자 화면에서 임계값을 낮춰 보이는 순간 카드 색은 바뀌는데 이벤트 목록에는 아무것도 안 생기므로, 그 자리에서 앞뒤가 맞지 않게 된다(그래서 임계값 탭이 그 사실을 화면에 먼저 적어 둔다, `05 §6.3`).
