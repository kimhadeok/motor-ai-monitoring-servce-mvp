# 모터 세부정보 — 모터 그래프 차트 세로 확대 (130px → 260px)

## Context

모터 세부정보 페이지의 "모터 그래프" 섹션은 차트 높이가 **130px**이라, 6시간 창에서 값이 조금씩 변할 때 선이 거의 수평으로 보인다. 변화 추이가 눈에 들어오지 않는다는 것이 이번 요청의 문제다.

다만 이 차트는 `app/ui/charts.py`의 `metric_graph_grid`를 **모터 그래프 페이지(`app/pages/motor_graph.py`)와 공유**한다. `charts.py:32`의 상수를 그냥 바꾸면 모터 그래프 페이지(최대 20대 × 4지표 = 80개 차트)까지 세로 2배가 되어 스크롤이 폭증한다. 사용자가 "일단 해당 페이지만"이라고 한 이유가 이것이다. 따라서 **높이를 인자로 받아 페이지별로 다르게** 주는 구조로 바꾼다.

확정된 값(사용자 선택):
- 차트 높이 **130 → 260px (2배)** — 모터 세부정보에만 적용
- Y축 눈금 **3개 → 5개** (0·25%·50%·75%·최상단) — 세로로 벌어진 만큼 값을 읽을 격자가 필요. 모터 세부정보에만 적용

## 변경 파일

### 1. `app/config.py` — 차트 높이·눈금 수를 config로 올린다

현재 `CHART_HEIGHT_PX = 130`은 `app/ui/charts.py:32`에 모듈 지역 상수로 **하드코딩**돼 있어 CLAUDE.md의 config 중앙화 규칙에서 벗어나 있다. 이번에 값이 화면별로 갈리므로 함께 config로 옮긴다.

- `DETAIL_CHART_REVEAL_MS`(`:201`) 아래, "모터 세부정보" 계열 상수 자리에:
  ```python
  DETAIL_CHART_HEIGHT_PX = 260
  DETAIL_CHART_Y_TICKS = 5
  ```
- "모터 그래프 페이지" 블록(`:218~`)에:
  ```python
  GRAPH_CHART_HEIGHT_PX = 130
  GRAPH_CHART_Y_TICKS = 3
  ```
- 주석에 **왜 두 화면이 갈라졌는지**를 남긴다: 모터 그래프는 여러 대를 나열하는 비교 화면이라 낮게 유지, 세부정보는 한 대만 보므로 변화 추이를 드러내기 위해 2배.

### 2. `app/ui/charts.py` — 높이·눈금 수를 인자로 통과시킨다

호출 체인이 `metric_graph_grid` → `_motor_charts` → `metric_chart` → `_y_ticks` / `.properties(height=...)` 라 3단계를 통과시켜야 한다. 기존 `show_motor_row`·`thresholds`와 같은 **키워드-온리 + 기본값** 패턴을 그대로 따른다.

- `:32` 지역 상수 `CHART_HEIGHT_PX` 제거 → `app.config`에서 `GRAPH_CHART_HEIGHT_PX`, `GRAPH_CHART_Y_TICKS` import (기존 import 블록 `:22-28`에 추가)
- `_y_ticks(fault)` (`:35`) → `_y_ticks(fault, tick_count)`. 상한(`top`) 계산은 그대로 두고 눈금값만 `tick_count`로 등분:
  `[round(top * i / (tick_count - 1), 2) for i in range(tick_count)]`
  - 기존 3개 동작은 그대로 재현된다(`[0, top/2, top]`).
- `metric_chart(df, metric, thresholds=None, *, height=GRAPH_CHART_HEIGHT_PX, y_tick_count=GRAPH_CHART_Y_TICKS)` — `:105`의 `.properties(height=height)`
- `_motor_charts(...)`, `metric_graph_grid(...)`에 같은 두 키워드를 추가해 그대로 전달
- **기본값이 모터 그래프 페이지 값이므로 `motor_graph.py:108`은 손대지 않는다.**

Y축 라벨 포맷(`:69` `format=".1~f"`) 확인 필요: 전류는 상한이 25라 5등분하면 6.25 / 18.75가 나오는데 `.1~f`는 이를 "6.3" / "18.8"로 반올림해 **격자선 위치와 라벨 값이 어긋난다.** `.2~f`로 바꾸면 6.25 / 18.75로 정확히 찍히고, 기존 3눈금 값(50 / 5 / 12.5 / 50)도 표기가 달라지지 않아 모터 그래프 페이지는 영향이 없다. → **`.2~f`로 변경**하고 화면에서 확인한다.

`_y_ticks`의 기존 주석("눈금 3개면 Vega가 최상단을 솎지 않는다")은 이번에 5개가 생기므로 **260px에서 최상단 라벨이 유지되는지 화면 확인 후 주석을 갱신**한다.

### 3. `app/pages/motor_detail.py` — 호출부에 전달

- `:33` import에 config 상수 추가, `:132-143` `metric_graph_grid(...)` 호출에
  `height=DETAIL_CHART_HEIGHT_PX, y_tick_count=DETAIL_CHART_Y_TICKS` 추가.
- 그 외 로직·레이아웃 변경 없음. CSS는 손대지 않는다 — `styles.py:412-419`의 차트 리빌 애니메이션은 `clip-path` 기반이라 높이와 무관하고, `.stVegaLiteChart`에 고정 height CSS가 없어 파이썬 인자만으로 반영된다.

## 검증

1. 코드 수정 후 **앱 재시작** (재시작 없이는 옛 화면이 그대로 보인다)
2. **다크 모드**로 모터 세부정보 페이지 진입 → "모터 그래프" 섹션 확인
   - 4개 지표 차트 세로가 2배(260px)로 커졌는가
   - Y축 눈금이 0·25%·50%·75%·최상단 5개로 찍히고, **최상단 라벨(100 / 10 / 25 / 100)이 솎이지 않는가**
   - 전류 차트에서 6.25 / 18.75가 격자선과 어긋나지 않게 찍히는가
   - 선·점 리빌 애니메이션이 그대로 재생되는가
   - 그래프 아래 "지표별 임계값"·이벤트 섹션이 깨지지 않았는가
3. **모터 그래프 페이지는 변화가 없어야 한다** — 높이 130px, 눈금 3개 그대로인지 대조 확인
4. 라이트 모드도 한 번 대조

검증은 사용자가 직접 할지, 제가 브라우저로 확인할지 실행 전에 확인받는다.

커밋은 검증이 끝난 뒤 대상 파일과 메시지 초안을 제시하고 승인받은 뒤에 한다.

## 실제 반영 범위 (2026-08-12 작업 종료 시점)

계획은 차트 높이·눈금까지였으나, 검증 중 **그래프가 15분 구간 평균이라 스파이크를 지운다**는 문제가 드러나 같은 세션에서 두 가지를 더 처리했다.

1. **차트 세로 2배 + Y눈금 5개** (계획대로, 모터 세부정보만) — 실측: SVG 260px, 눈금 5개 전부 표기, 모터 그래프 페이지는 130px·3눈금 유지. 라벨 포맷 `.1~f` → `.2~f`.
2. **모터 세부정보 원본 표시 전환** — `get_motor_metric_raw_series()` 신설. 근거: 한 15분 구간에서 온도 원본 최대 38.27 → 평균 33.14(−13%), 19,920구간 중 18구간(0.1%)은 평균과 원본 최대의 상태 구간이 달랐다. 실측: 지표당 2,026점 · 쿼리 3.0ms · spec 156ms · 630KB · 렌더 1,599ms.
3. **모터 그래프 페이지도 원본 표시로 전환** (사용자 요청, "일단 적용하고 눈으로 보고 조정") — 실측: 20대 기준 선분 52,712개 · spec 1,195ms · 4.1MB · 렌더 1,343ms. 10대는 41,980선분 · 3.2MB · 렌더 1,638ms.

되돌릴 여지로 `get_motor_metric_series`(평균)와 `GRAPH_TREND_BUCKETS`를 남겨 뒀다. 배포 환경에서의 전송·렌더 시간은 **미검증**이다.

### 이후 이름·값이 바뀐 것 (같은 날 후속 작업)

- `*_Y_TICKS`(눈금 개수) → **`*_Y_DIVISIONS`(단계 수)**, 인자도 `y_tick_count` → `y_divisions`. 상한을 등분해야 눈금이 나이스 숫자로 떨어져서다. 그래프 페이지 2단계(눈금 3), 모터 세부정보 **10단계**(눈금 11, 사용자 요청으로 4 → 10).
- 모터 그래프 페이지: 창 6 → **3시간**, X축 **30분** 눈금 고정, 차트별 지표 상태 배지, 행 머리 `(모터명)  -  상세 보기 ›` 버튼.
- 모터 세부정보: 창은 6시간 유지(`DETAIL_TREND_HOURS`), 차트별 지표 상태 배지 추가.
