    무엇이 달라졌는지 알아채지 못한다. `_changed_metrics()`가 직전 렌더 값과 비교해 **바뀐

    카드 스파크라인은 차트 라이브러리가 아니라 좌표를 이어 붙인 인라인 SVG polyline이라

    ② **전이가 확정된 시각의 행과 그 직전 행** — 이벤트 목록의 "값 변화"가 `time = created_at`으로 정확히 조인하고 직전 행을 서브쿼리로 가져오며(`services/events.py`), 리포트도 같은 시각의 행이 없으면 아예 생성되지 않는다(`reports/service.py`). 이 두 행이 빠지면 화면이 조용히 빈다
    ③ 그 밖의 구간은 `SEED_SPARSE_INTERVAL_SECONDS`(900초) 간격
  - **실측**: 288,210행 3.80초 → **81,858행 1.95초**(-72% 행, -49% 시간). 전이 80건·알림 24건·모터 210대 불변. 이후 2번(자동 갱신)에서 FAULT 4대를 10초 주기로 돌리며 **92,997행 2.62초**가 됐다(부트스트랩 전체 3.29초).
    간격별: 300초 149,029행 2.88초 / 600초 98,650행 2.04초 / **900초 81,858행 1.95초** / 1800초 65,067행 1.90초. 300초는 벌크 수집 주기와 같아 효과가 없고, 900초를 넘기면 생성 루프(1.70초)가 바닥이라 더 줄지 않는다.
  - **이 방식의 하한**: 시드 시간은 생성 1.67초 / INSERT 2.06초 / commit 0.07초로 나뉜다(실측). 저장만 줄이므로 생성 1.70초는 남는다.
  - **①은 채택하지 않았다** — 벌크 주기를 늘려도 이미 900초 간격으로 솎아내 효과가 없고, 반대로 줄이면(60초 → 시드 5.73초) 이 항목이 되돌아간다. 2번의 "카드가 5분마다 움직인다"와 맞물린 결정이다.
  - ~~**미검증**: 배포 환경에서 실제로 얼마나 줄지~~ → **2026-08-12 배포 로그로 확인.**
    ```
    부트스트랩 완료 | 모터 210대 텔레메트리 92,997행 상태로그 80건 | reseeded_stale=False
    ```
