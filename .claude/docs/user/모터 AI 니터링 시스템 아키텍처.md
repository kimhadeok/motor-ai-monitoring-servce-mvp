### 모터 상태 모니터링의 4가지 영역 구분
상태 변화 값(State Value) 기반의 초기 판단의 장점

모터 상태 NORMAL, WARNING, DANGER, FAULT (범위별 값 지정)
상태 전이(State Transition)가 일어났을 때만 이벤트 메시지(예: WARNING -> DANGER)를 내부 메시지 큐(RabbitMQ, Redis Pub/Sub 등)에 딱 1개 발행

🛠️ 최종 완성된 모터 AI 에이전트 모니터링 아키텍처

1. 가벼운 데이터 관리 (슬라이딩 윈도우)
에이전트는 거대한 영구 DB를 뒤지는 대신, 모터별로 '최근 2시간 치 데이터'만 가볍게 들고 다니며 맥락을 유지합니다.

2. 상태 기반 1단계 필터링 (NORMAL ➔ WARNING ➔ DANGER ➔ FAULT)
수치의 잦은 흔들림(핑퐁)을 막기 위해 상태 값의 변화(Transition)를 기준으로 삼습니다.

3. 상태별 스마트 대응
NORMAL ➔ WARNING: 조용히 이벤트 로그만 쌓아두어 추후 전조 증상 분석용 맥락(Context)으로 활용합니다.
WARNING ➔ DANGER: AI 에이전트가 즉시 출동하여 2시간 윈도우 + RAG 매뉴얼로 진단하고 알림을 보냅니다.
FAULT: 이미 정지된 상태이므로 사후 분석용 리포트 대기 모드로 전환합니다.

4. 쿨다운 타임 적용
DANGER 진입 시 에이전트가 동작하면 설정된 시간(예: 1시간) 동안은 중복 개입을 차단하여 알람 폭탄과 서버 부하를 방지합니다.

* 모든 모터를 하나의 그래프로 모두 표시 (온도, 진동, 속도, 소리 들어오는 값)
* 모든 모터를 하나의 그래프로 모두 표시 (상태 변화 값)

* 모터별 온도, 진동, 전류, 소리 20초(또는 10초, 30초) 들어오는 값 마다 화면에 표시되는 그래프 (실시간)
  (API 통해 48시간 범위 데이터만 등록 관리)

* 모터별 온도, 진동, 전류, 소리 현재 상태를 색깔로 표시
* 모터별 온도, 진동, 전류, 소리 상태 변화 값 표시
